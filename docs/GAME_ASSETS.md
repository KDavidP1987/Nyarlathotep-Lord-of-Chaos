# Game assets — using the reference data

`Reference Data/` (gitignored, read-only) holds the V Rising asset record this mod targets. Look a
prefab up here **before** writing code that spawns, buffs, or reads it: confirm the GUID and confirm the
components you plan to touch actually exist on that prefab.

| File | What it is | Source |
|---|---|---|
| `Prefabs/` | 23,535 component dumps, one per prefab: `<PrefabName> PrefabGuid(<int>).txt` | Beelzebub `Reference Data/Prefabs` (game build matching VampireReferenceAssemblies 1.1.12) |
| `prefab_names.tsv` | `<guid>\t<name>`, no header, 23,534 rows — fast name↔GUID lookup | Beelzebub `Resources/` |
| `unit_index.tsv` | Every `CHAR_*` unit: `guid, name, faction, level, vblood, minion, health_settings` (533 rows, 90 V Bloods) | Generated here from `Prefabs/` (2026-09-23) |
| `script_edges.tsv` | `<sourceGuid>\t<targetGuid>\t<Component.Field>`; 773 rows are `Script_ApplyBuffUnderHealthThreshold_DataServer.NewBuffEntity` = **boss health-phase buffs** | Beelzebub `Resources/` (generated by its `tools/build_script_edges.py`) |

Regenerate `unit_index.tsv` after a game update re-dump (the one-liner is in `RESEARCH_NOTES.md` §Tools).
If the prefab dump is refreshed for a new game build, refresh it from the Beelzebub workspace (the
canonical copy) and re-run the index.

## Lookup recipes

- Unit by keyword: glob `Reference Data/Prefabs/CHAR_<Faction>_<keyword>*.txt`
- Buff: `Buff_*`; ability: `AB_*`; castle pieces: `TM_*`; drop tables: `DT_*`; AI behaviours: `BEH_*`
- All units of a faction: filter `unit_index.tsv` on the `faction` column.
- A boss's phase buffs: `script_edges.tsv` rows whose source is the boss GUID. **Ignore target
  `-359018142` (`Buff_General_Station_Repair`)** — a placeholder that appears in many rows.

## Unit prefab anatomy (what we read and write)

From `CHAR_Bandit_Thug PrefabGuid(-301730941)` — typical of every `CHAR_*` NPC:

| Component | Field(s) | Why Nyarlathotep cares |
|---|---|---|
| `FactionReference` | `FactionGuid` | **Faction targeting** for empowerment; faction swap for turned units |
| `UnitLevel` | `Level` | Level override for event spawns (drives level-difference damage) |
| `UnitStats` | `PhysicalPower`, `SpellPower`, resistances… | Damage scaling (prefer buffs over direct writes) |
| `Health` | `MaxHealth`, `Value` | HP scaling |
| `AggroConsumer`, `Aggroable`, `AggroBuffer` | `Active`, `PreCombatPosition` | Making spawned units actually engage |
| `AiMove_Server` | `MovePattern` | Movement behaviour |
| `BehaviourTreeState` | `Value` (`GenericEnemyState`) | Force Combat/Follow, stop "Return" leashing |
| `Team`, `TeamReference` | `Value` | Who is hostile to whom |
| `DropTableBuffer` | `DropTableGuid` | Clear to make event spawns lootless (anti-farm) |
| `EntityCategory` | `UnitCategory` | Filter out critters/structures |
| `VBloodUnit` / `VBloodConsumeSource` | — | **Is this a V Blood** (present only on bosses) |

## Boss reinforcement data

`Beelzebub/Beelzebub/Patches/AbilityCastStartedSystemPatch.cs` (`SummonTargets`, ~lines 56-133) maps boss
summon abilities to the unit they spawn — e.g. Tourok → `CHAR_Bandit_Thug` -301730941 ×2; Raise Dead →
`CHAR_Undead_SkeletonSoldier_Base` -603934060. Good default "adds" per boss. Boss-part units with
`BehaviourTreeInstance.Immobile=true` (e.g. Morgana's tail) will not fight on their own — never use them
as adds.

## Do-not-spawn list (known crashers)

- `CHAR_Mount_Horse_Vampire` -1502865710 and `CHAR_Mount_Horse_Gloomrot` — crash the server on spawn
  (KindredCommands NOSPAWN list).
- Any `CarriagePrisonerRelease*` / `MicroPOI*` prefab — embedded endless NPC-wave spawners (Uriel lesson).
- Prefabs carrying `DropInInventoryOnSpawn` — crashed the server (`AppendRemovedComponentRecordError`).
- Units with `BehaviourTreeInstance.Immobile = true` — boss parts; inert on their own.

Ship this as a hard-coded deny-list in the spawn service; admins can extend it, never shrink it.
