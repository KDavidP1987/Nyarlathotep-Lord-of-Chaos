## Review 1 · 2026-09-26 · codex · plan: the first draft (uncommitted)
F1 `blocking` — Probe `3.3` is unanswered: the feature emits persistent BepInEx and server log records, including admin-command, reload, template-validation, and pillar lines, but Design › Data specifies retention/deletion only for temporary soak copies, not the source logs.  
Fix: add the source logs to the artifact inventory with location, owner, rotation/retention, deletion, and copy count, and make the D30 inventory command fail when that row is absent.

F2 `blocking` — Probe `4.1` is unanswered: the Epic’s inherited “durations are hard” rule is neither restated nor specifically incorporated by reference; fixed template values and “running instance keeps its definition” do not define what “hard” means at expiry.  
Fix: reference the Epic Business rule explicitly or state that each instance ends at its configured duration without extension, pause, stacking, or replacement, with a D-item testing that invariant.

F3 `blocking` — Probe `4.4` is unanswered: the plan defines readiness and start precedence but never says who may authorize an exception, while the cited `ReadinessTests` command cannot fail if start precedence or exception authority is removed.  
Fix: state that precedence admits no runtime exception—or name its decision authority—and add one evidence command whose tests cover purge, master switch, pillar, concurrency limit, definition state, and the exception rule.

F4 `blocking` — Probe `4.2` is contradicted by S-13: its fallback permits VBlood and Manual templates to be proved in Session 2 instead of the soak, violating the inherited invariant that every shipped template runs in the soak before release.  
Fix: make inability to run all six templates in the soak a release blocker; a split soak is acceptable only if every template still starts and ends within the combined soak evidence.

F5 `blocking` — Probe `6.2` is unanswered as a control: `DependencyFailureTests.Library` covers file, cfg, and catalogue failures, but cannot fail when VCF, ProjectM position/clock access, git, gh, GitHub, or Codex is slow, unavailable, or malformed despite those dependencies being claimed by the layer.  
Fix: state actionable behavior for every dependency class and nominate a single executable evidence command that exercises or statically verifies each behavior.

F6 `blocking` — Probe `12.4` is unanswered because the selftest matrix delegates release, rollback, audit, session, and path fixtures “as faction-empowerment,” and the gating matrix’s 4.4 and 6.2 commands cannot fail for all controls they claim; therefore the required failing, silent, and empty inputs are not concretely evidenced.  
Fix: reference exact sibling sections/fixtures and extend the registered selftest so every gating command has a planted failing case, a valid silent case, and a non-passing empty case matching real spellings and outputs.

F7 `blocking` — Probe `14.4` is unanswered: Paths walked omits files regenerated by the stated `dotnet build/test` and release operations, such as project `bin/**` and `obj/**`, while D30 claims every walked path is manifested.  
Fix: enumerate those generated paths or reference existing manifest entries explicitly, then ensure `preflight.ps1 -Paths` plants an unmanifested generated path and fails.

F8 `advisory` — S-11 is not cheaply reversible: its fallback bypasses BepInEx `ConfigEntry`/`ConfigFile.Save`, directly contradicting the Epic’s inherited cfg-write constraint and adding a new persistence implementation.  
Fix: retain ConfigEntry/Save as the invariant and treat unexpected formatting changes as a release blocker or acceptance-policy amendment.

F9 `advisory` — S-7 and S-8 understate reversibility: changing pillar-off lifecycle semantics or adding an indexed chat-field contract affects services, documentation, tests, and compatibility, not merely “one planner” or “one row.”  
Fix: describe the actual affected surfaces and require an amendment before selecting either fallback.

F10 `advisory` — Concurrent deletion remains ambiguous: if admin A arms deletion, admin B deletes the event, and A then confirms, the plan does not specify whether A receives “unknown event,” “no delete pending,” or another result (`7.2`).  
Fix: choose the deterministic response and add it to AuthoringTests.Delete.

F11 `advisory` — The 1 MB boundary names the excluded valid case but does not state the exact chat response or byte-preservation evidence when a proposed write crosses it (`13.2`).  
Fix: specify the refusal text and include an over-limit fixture in AuthoringTests.Equivalence.
