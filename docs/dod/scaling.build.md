# Build view: Scaling to the players — wave and horde sizes and levels follow the players in scope

Generated from `scaling.md` by `dod-wbs.mjs --build`; it is not the source of truth. Change the plan, then run `--build` again.

**North Star:** a server admin can let any wave or apocalypse event grow with the players it is meant for, with more units per extra player and levels near their gear, inside the caps and the tick budget, off unless the admin adds it, released as 0.14.0; finished when D1-D27 have evidence.

Risk: (none stated)

## Components
- C1 · **Opt-in block** an admin turns scaling on for one event in events.json or in chat, sees it in `event info`, and an event without it is unchanged · D1 D14 D15 D16 D18
- C2 · **Who is counted** the living online players in the event's scope, admins as the scoreboard switch says, read fresh before each wave, horde or top-up · D2 D4 D12 D19 D20 D21
- C3 · **Scaled counts** each extra player adds the admin's number of units to each entry of a wave, a fan-out group, a horde or a top-up, inside the caps · D3 D4 D5 D9 D20 D21
- C4 · **Scaled levels** units take the players' average gear level plus the offset and the per-wave growth, clamped 1-120, V Bloods keeping theirs · D6 D7 D8 D19 D20 D21
- C5 · **Safe to ship** one line per decision, names nowhere, guarded reads, the tick budget, older events unchanged, a drilled rollback, a release and the records · D10 D11 D12 D13 D17 D18 D22 D24 D25 D26 D27
- C6 · **Fair in play** a group of real players meets a wave that feels sized and levelled for them, as the owner judges · D23
