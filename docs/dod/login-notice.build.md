# Build view: Login notice — a player who logs in during a running event is told what is running

Generated from `login-notice.md` by `dod-wbs.mjs --build`; it is not the source of truth. Change the plan, then run `--build` again.

**North Star:** every player who logs in while an event is running gets one private line naming the running events and their time left, on by default and switchable off in the cfg, shipped as 0.13.1 during the players' test weekend; finished when D1-D12 have evidence.

Risk: (none stated)

## Components
- C1 · **The notice** one private line at login naming every running event and its time left, as `.nyar status` shows them · D1 D2 D7
- C2 · **Admin control** on by default, off with one cfg switch, its default guarded by preflight · D3
- C3 · **Safe to ship** contained failures, wire and privacy unchanged, registered controls, a drilled rollback, a recorded release · D4 D5 D6 D8 D9 D10 D11 D12

## Items
- [ ] D1 · **Notice text** new `Messages.LoginNotice(running, utcNow, own)` returns null when no instance runs, else one line "Events in progress: <name> (<n> min left)[; <name> (<n> min left) …]. Type .nyar status for details." with the instances ordered by end time, each part the text `.nyar status` shows for it (an apocalypse's own status line through `own`, Messages.Status's "<n> min left" otherwise), cut to Wire.MaxBytes (512) by whole parts and ending "… and <m> more" when parts are left out; it holds no coordinate, zone radius, player name or platform id · fails when: a line is returned with nothing running, a part is out of end-time order, a line passes 512 bytes or cuts a part in half, the "… and <m> more" count is wrong, or a part differs from the status line of the same instance
- [ ] D2 · **Who gets it, when** new `LoginNotices` in Logic/AnnouncerCore.cs with an injected clock: every user who connects, admin or not, while LoginEventNotice is on is queued once; the notice leaves 10 s after the connect (NoticeDelay) and its running list is read when it leaves, so a user is sent nothing when no event runs at that moment, when they disconnected or another player holds their user entity (platform id changed), or when they connected again within 60 s of their previous connect (its own LoginGate, separate from the admin degraded notice's, so a degraded admin still gets that notice too); an "event" is an instance in EventStore.Catalog.Running (started and not ended), never a definition that is only enabled · fails when: a notice leaves before 10 s, is sent with nothing running at its due time, reaches a disconnected or replaced user, is sent twice within 60 s of reconnects, is sent for an enabled event that is not running, skips a non-admin, or stops the admin degraded notice
